========================================================================
PART 1: 2D Isocontour Extraction
========================================================================

Running the Program:

The script takes the isovalue as a command-line argument.

Syntax:

python simul.py <isovalue>

Examples:

python simul.py 0
python simul.py -600
python simul.py 300

Input:

<isovalue> : Floating-point value specifying the contour value to be extracted.

Output:

The program generates a VTK PolyData (`.vtp`) file containing the extracted isocontour.

Output file name format:

contour_<isovalue>.vtp

Examples:

contour_0.vtp
contour_-600.vtp
contour_300.vtp

Visualization:

The generated `.vtp` file can be opened directly in ParaView for visualization of the extracted isocontour.

Special Cases:

1. Isovalue Outside Scalar Range
If the specified isovalue lies outside the scalar range of the dataset, the program displays a warning message. Since no contour can exist outside the scalar range, the generated output will contain no contour segments.

2. Ambiguous Cell (Four Intersections)
In certain cells, the isocontour may intersect all four edges of the cell, producing four intersection points. As specified in the assignment, ambiguity resolution techniques such as the Asymptotic Decider are not implemented.

The cell edges are traversed in the following counterclockwise order:
Bottom → Right → Top → Left

The intersection points are stored in this order, and two contour segments are generated by connecting consecutive pairs of intersections:
(Bottom, Right)
(Top, Left)

This follows the prescribed edge traversal order while avoiding ambiguity resolution.

========================================================================
PART 2: 3D Volume Rendering and Transfer Functions
========================================================================

Running the Program:

The script takes a string parameter as a command-line argument to enable or disable advanced shading.

Syntax:

python volume_render.py <phong_shading_option>

Examples:

python volume_render.py yes
python volume_render.py no

Input:

<phong_shading_option> : A string value ('yes' or 'no') specifying whether the user wants to use advanced Phong shading.

Output:

The program executes completely in the background via off-screen rendering using a strict 1000x1000 canvas window. It automatically writes out two high-fidelity PNG image captures representing opposite camera orientations.

Output file names dynamically vary based on the input argument:

If run with 'yes':
- front_with_phong.png
- back_with_phong.png

If run with 'no':
- front_without_phong.png
- back_without_phong.png

Visualization and Setup Specifications:

1. Transfer Functions
The script initializes explicit 1D color and opacity mapping curves based on simulation pressure intervals defined in the specification tables:
- Color Transfer Points: Linearly interpolates RGB nodes ranging between Cyan at -4931.54, deep Blue, red, orange, and Yellow at 2594.97.
- Opacity Transfer Points: A piecewise ramp mapping full opacity (1.0) at -4931.54 down to near-complete transparency (0.002) at 101.815, and completely invisible (0.0) at 2594.97.

2. Bounding Framework
A structural geometric outer frame is applied over the volume-rendered scalar data using a `vtkOutlineFilter`. The actor property is configured with a black color profile and a line width of 2 to define clear spatial boundaries.

3. Illumination Model (Advanced Shading)
When the shading parameter is toggled to 'yes', a realistic Phong interpolation model is evaluated with uniform material lighting parameters:
- Ambient Coefficient: 0.5
- Diffuse Coefficient: 0.5
- Specular Coefficient: 0.5

Camera Orientation Cases:

1. Baseline Tracking (Back View)
The initial tracking camera position faces the baseline data grid projection. The system resets the active clipping boundaries and renders this viewpoint as the baseline snapshot.

2. Orbital Traversal (Front View)
To capture the true internal front structure of the simulation volume, the camera undergoes a complete 180-degree azimuth rotation around the focus center vector. The scene boundaries are recalculated to prevent pixel clipping prior to exporting the final frame.
